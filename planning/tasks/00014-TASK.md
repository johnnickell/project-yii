# Keep Yii Post-Merge Routing and Delivery Handoffs Current

## Outcome

The maintainer approved this standalone tooling repair after PR #16 had already merged but read-only routing
repeated the Board's obsolete human-merge instruction. Port the preventive behavior from Fight Common's
[TASK-00176 / PR #234](https://github.com/johnnickell/fight-common/pull/234), adapted to Yii's stronger local
validation and authored Wayfinder views. Routine verified human merges must not require another maintainer cleanup
request before routing can continue. Preserve truthful delivery evidence, read-only/offline checks and fail-closed
handling of real uncertainty.

Approval accepts this scope and record creation, not implementation completion, independent acceptance, publication
or merge. The maintainer selected the main checkout. Implementation belongs on
`feature/task-00014-current-delivery-handoffs`, created from `develop` after this approved planning baseline is
integrated. Preserve the existing authorized planning branch and its PR #16 reconciliation/instruction changes;
do not silently discard them, duplicate their current handoff, commit directly to `develop`, or mix in the WF-001 audit.

At `2026-10-25T03:18:43Z`, `./bin/planning-check` passed with **21 records, 3 active, 0 views refreshed**, although
Board Now still described TASK-00009's PR #16 as OPEN and instructed human review/merge. The Roadmap and parent

With `GIT_NO_LAZY_FETCH=1 git --no-replace-objects merge-base --is-ancestor`, both published-head → merge and
merge → local HEAD checks succeeded. TASK-00009 was already `done`; neither missing integration nor unresolved
implementation was the cause. Its [current integration record](00009-TASK.md#current-integration--pr-16) preserves

`scripts/planning_portfolio.py` validates records and generated status/dependency tables, but does not generate
current routing/delivery summaries or verify live PR state. Its offline success cannot detect stale authored merge
prose. The immediate authorized prose correction and [manual verification rule](../CONVENTIONS.md#live-handoff-verification)
are not the preventive automation requested here.

## Scope

- Generate Board current execution/delivery and Roadmap execution summaries from authoritative TASK metadata,
  preserving approved human decisions/history and the separate planning/decomposition handoff.
- Introduce an optional explicit current-delivery marker on live TASKs, set at verified OPEN publication. `done`,
  a PR link and historical publication prose alone never establish a current handoff. Generated delivery text
  records publication with a live-verification requirement, not an unconditional OPEN claim.
- Add `./bin/planning-check --check-delivery`: bounded, read-only live verification of explicit current handoffs
  only, using existing operator `gh` access. Exact verified MERGED/integrated `done` work resolves read-only and
  routing continues even before its recorded publication snapshot is retired. OPEN remains a human handoff.
- Add `./bin/planning-check --reconcile-delivery` at authorized Work, Land or substantive planning intake. Validate
  all records, live evidence and planned output before writing; retire only verified ended markers, preserve exact
  merge evidence and unrelated bytes, and refresh views. Repeat retirement is a query-free, byte-identical no-op.
- Keep ordinary planning checks and `./bin/build` offline/read-only. Reject stale generated current summaries
  before expensive product checks and retain the final planning phase. Require bounded live delivery checks at
  read-only routing and Land intake/pre-publication/final handoff boundaries, not network-dependent product gates.
- Reconcile affected root routing, conventions, local workflow binding and contributor guidance with the supported
  commands. Preserve Yii's tracked-Markdown validation, record checks, priority semantics and authored Wayfinder
  tables/frontiers; do not wholesale-replace its validator with Common's different projections.

Out of scope: product PHP/API behavior, dependency adoption, framework certification/receipt mechanisms,
automatic fetch/merge/publication, hosted-CI success requirements, network-dependent build, historical PR scanning,
independent report rewriting, release/deployment, archiving and the separate WF-001 package audit. No new parent
TICKET/EPIC, public Composer API or copied package Domain/Application implementation is needed.

## Commands, queries, events and permissions

Tooling only; business commands/queries/events and application permissions are N/A. Inputs are local authoritative
records, exact current PR metadata and local Git objects. Existing operator access permits only bounded read-only
queries; missing credentials/tools do not authorize setup or disclosure. Ordinary checks, live checks, routing,
Review and QA do not retire metadata. Explicit authorized reconciliation may write only ended handoff evidence,
marker retirement and generated projections. It cannot create implementation/review/QA/merge authority.

## Acceptance Criteria

- [ ] Repeated normal publication/human-merge cycles resolve read-only without routine cleanup requests. OPEN
  stays pending; verified MERGED/integrated `done` work resolves without inferring independent acceptance or QA.
- [ ] Current summaries are generated from one authoritative TASK ordering/classification. Return every active
  TASK, otherwise the first executable Ready Frontier row; preserve completed blocker edges, all valid positive
  ranks, Human Action/Needs Info and first triage/waiting reasons. Keep planning decomposition distinct.
- [ ] Live checks query only explicitly current handoffs, with finite request/output bounds. Validate exact origin,
  repository, URL/number, TASK/title, feature branch, `develop` base, published head, state and merge identity/time.
  MERGED resolution requires existing `done` scope and local published-head → merge → HEAD ancestry, with Git
  replacement objects and lazy fetching disabled. No fetch is performed.
- [ ] Closed-unmerged, non-terminal scope, identity mismatch, unavailable/malformed/oversized/contradictory metadata,
  missing objects or unintegrated merges fail closed with the precise owner/input gap. Live failures cause no
  planned writes, including partial retirement/view refresh when several handoffs are checked.
- [ ] Explicit reconciliation retires only verified ended markers, preserves historical publication/acceptance/QA,
  exact observed head/merge/time/local-HEAD evidence and unrelated metadata/body bytes/line endings. Match the
  reader's accepted whitespace-key semantics and validate planned frontmatter before writing. Retired PRs are not
  queried again; repeated retirement is idempotent and OPEN markers remain.
- [ ] Ordinary checks/build remain offline, credential-independent and byte-for-byte read-only. Generated-summary
  drift fails before expensive checks; the final planning phase remains. Existing Yii validation/rollup guarantees
  and authored Wayfinder decisions are retained without importing Common's unrelated validator behavior.
- [ ] Local instructions agree on check versus reconciliation effects, authorized intake and final Land freshness.
  Validate normal post-merge continuation and unavailable/uncertain evidence walkthroughs. No provider mutation,
  routine cleanup gate or publication authority is introduced.
- [ ] Direct regression-first tooling probes and complete local gate evidence are retained. Independent Review
  and applicable nonvisual QA remain separate requirements before completion/publication.
