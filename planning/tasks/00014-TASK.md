## Scope

- Generate Board current execution/delivery and Roadmap execution summaries from authoritative TASK metadata,
  preserving approved human decisions/history and the separate planning/decomposition handoff.
- Introduce an optional explicit current-delivery marker on live TASKs, set at verified OPEN publication. `done`,
  a PR link and historical publication prose alone never establish a current handoff. Generated delivery text
  records publication with a live-verification requirement, not an unconditional OPEN claim.
- Add `./bin/planning-check --check-delivery`: bounded, read-only live verification of explicit current handoffs
  only, using existing operator `gh` access. Exact verified MERGED/integrated `done` work resolves read-only and
  routing continues even before its recorded publication snapshot is retired. OPEN remains a human handoff.
- Add `./bin/planning-check --reconcile-delivery` at authorized Work, Land or substantive planning intake. Validate
  all records, live evidence and planned output before writing; retire only verified ended markers, preserve exact
  merge evidence and unrelated bytes, and refresh views. Repeat retirement is a query-free, byte-identical no-op.
- Keep ordinary planning checks and `./bin/build` offline/read-only. Reject stale generated current summaries
  before expensive product checks and retain the final planning phase. Require bounded live delivery checks at
  read-only routing and Land intake/pre-publication/final handoff boundaries, not network-dependent product gates.
- Reconcile affected root routing, conventions, local workflow binding and contributor guidance with the supported
  commands. Preserve Yii's tracked-Markdown validation, record checks, priority semantics and authored Wayfinder
  tables/frontiers; do not wholesale-replace its validator with Common's different projections.

Out of scope: product PHP/API behavior, dependency adoption, framework certification/receipt mechanisms,
automatic fetch/merge/publication, hosted-CI success requirements, network-dependent build, historical PR scanning,
independent report rewriting, release/deployment, archiving and the separate WF-001 package audit. No new parent
TICKET/EPIC, public Composer API or copied package Domain/Application implementation is needed.
