# Bind Shared Engineering and Agent Workflows to Yii

## Outcome

Adopt shared engineering, planning, skill, and delivery conventions as Yii's default through a concise local
binding, preserving native Yii integration and stronger local guarantees. Implements the approved
[TICKET-00005](../tickets/00005-TICKET.md), not a provider installation or application migration.

## Scope

- In scope: focused AGENTS/conventions/architecture/contributor guidance reconciliation; a small binding in an
  existing or justified local document; explicit shared-rule applicability and Yii exceptions; canonical evidence
  paths; skill/resource substitutions; readable workflow handoffs; direct instruction verification.
- Out of scope: package/PHPCS updates (TASK-00008), gate replacement (TASK-00009), application/test refactors,
  copied skills, global Pi settings, enrollment/provider calls, publication, releases, and evidence relocation.
  Use the approved main checkout on its own feature branch after TASK-00011 is integrated; do not build on an
  unrelated unaccepted branch merely because the checkout is already selected.

## Acceptance Criteria

- [ ] Shared standards are the default for engineering and delivery, with source-linked local ownership and
      explicit Yii-native/stronger-guarantee exceptions. No provider application assumptions, speculative layers,
      package aliases, copied policy catalogs, private machine paths, or claims of complete code conformance.
- [ ] The binding covers every skill category in TICKET-00005, resolves local templates/context/map-phase/PR-body
      and runtime substitutions, and reports missing resources precisely. Provider instructions remain with
      the provider; Yii remains the target throughout nested references and delegated handoffs.
- [ ] New coordination/report evidence uses canonical base-owned shared paths; the dated coordinate-build rule
      is explicitly superseded without moving old evidence. Independent report ownership, runtime `var/`,
      native tools, explicit checkout choice, and existing authorization boundaries remain intact.
- [ ] next uses bounded Board/Wayfinder reads and one read-only validator, returns all active work or the first
      executable ready TASK, and never executes a recommendation. Confirm explicit-only next/build availability
      without installing/copying skills or silently changing invocation authority.
- [ ] Work, independent Review, behavioral QA, Land, and Build coordination have accurate target-bound handoffs,
      report identities, revision allowance/continuation, publication limits, and parent-completion semantics.
      Missing required hosted proof remains distinct from optional checks and local verification.
- [ ] Preserve exact Unit-only coverage and no-tests-of-tools/certification rules. Keep package and gate owners
      separate, distinguish current gate behavior from planned replacement, and record concrete conflicts rather
      than weakening requirements or claiming instruction changes repaired source.
- [ ] Document optional Jev enrollment, separate harness/skill discovery, native tool behavior, and lack of OS
      isolation. No credentials, settings, enrollment, paid calls, model changes, or extra installation occurs.
- [ ] Direct normal and failure/ambiguity walkthroughs, planning/link validation, diff checks, and the complete
      current canonical gate pass. Record walkthrough/runtime limitations and independent-review/QA status.
