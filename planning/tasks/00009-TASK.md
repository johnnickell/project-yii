# Replace the Disposable Build with a Running-Container PHP Gate

## Outcome

Deliver the approved gate lifecycle after stable package adoption, with explicit local/CI preparation and unchanged
coverage strength. Use this checkout on a dedicated feature branch; this is independent of the broader Wayfinder.

## Scope

Thin `bin/build`, PHP phase orchestration, focused wrapper integration, required tool availability in the existing
Compose service, hosted setup, and runtime/contributor documentation. No package updates, broader service topology,
product workflows, Python orchestration of the new gate, or tool-testing product suites.

## Acceptance Criteria

- [ ] `./bin/build` invokes named fail-fast PHP phases inside the running Compose PHP service; it fails with setup
      guidance when prerequisites are absent and never builds images or installs dependencies.
- [ ] Keep Composer validation, syntax/formatting checks, existing planning validation, Common PHPCS, PHPStan,
      Deptrac, Rector dry-run, applicable FPM validation, and every configured Unit/Integration/Functional suite.
      Run each retained suite exactly once, including justified frontend/browser suites only if configured;
      do not introduce suites to test tooling.
- [ ] Preserve exact 100% Unit-only owned-production statement coverage and missing-file/ignore rejection without
      baselines or coverage-ignore directives. Direct Unit tests use `#[CoversClass]`; retained boundary/journey
      suites use `#[CoversNothing]`. Replace bespoke policy/coverage-verifier machinery with direct attribution
      and standard coverage-tool enforcement, not a renamed custom verifier. Combined-suite coverage must not
      mask gaps; prefer one coherent PHPUnit run only with demonstrated Unit-only attribution.
- [ ] Remove remaining policy/coverage-verifier machinery and historical candidate validation, lowest/latest lanes,
      receipts/authorities, auxiliary locks/digests, and Fight Common certification journeys from ordinary builds;
      account for items already absent rather than recreating them. Retire disposable production installation/boot
      explicitly. Preserve valuable Yii HTTP, console, credential-rejection and adapter journeys and inward
      Adapter → Application → Domain boundaries without overstating production-install evidence.
- [ ] Local setup and hosted CI explicitly start the environment and install the lock before the same `./bin/build`;
      runtime remains non-root and focused repository wrappers remain usable.
- [ ] Document the changed setup contract and supersession of TASK-00005; verify the normal gate and useful
      prerequisite-failure behavior directly, without invalid source fixtures or tests of tools.
- [ ] Focused checks, planning validation, diff checks, and the final canonical gate pass; hosted evidence is recorded
      separately from local proof and never claimed without an actual hosted run.

## Verification

Run explicit setup with repository commands, inspect phase ordering/exit behavior and suite counts, run focused
behavioral checks and the new `./bin/build`, and record coverage-driver/denominator evidence. Validate CI preparation
by direct workflow inspection and equivalent local commands; report hosted execution only when available.
Validate missing-source and ignore rejection, coverage attribution, and removal of obsolete machinery by direct
owning-tool inspection/checks; do not add product tests of scripts, CI, configuration, coverage tooling, receipts,
certification fixtures, or docs, and do not seed deliberately invalid fixtures.
