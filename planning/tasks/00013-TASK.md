# Refresh and Enforce Patched Yii Container Runtimes

## Outcome

Ensure the existing local/CI PHP runtime and local NGINX service use patched container images rather than
silently retaining vulnerable cached versions. On 2026-10-24 the maintainer approved the diagnosed scope,
urgent priority, and standalone TASK creation, preserving the previously chosen isolated worktree.
This record accepts scope; implementation, independent review, publication, and deployment remain separate.

## Scope

- In scope: explicit patched PHP 8.5 and NGINX image versions; bounded image-refresh/recreation behavior and
  documentation; direct runtime/configuration checks; evaluation of PHP's follow-up session-upload-progress
  advisory against the actual application configuration; existing local/CI build and HTTP/console verification.
- Out of scope: Composer/package upgrades, application features, broader build orchestration changes owned by
  TASK-00009, certification machinery, deployment, incident response, secret rotation, and other ecosystems
  mentioned in the report. Do not weaken TLS verification or memory protections as a substitute for patching.
- Ownership: `etc/docker/fpm/Dockerfile`, `etc/docker/nginx/Dockerfile`, and narrowly necessary existing
  startup/build wrappers and runtime documentation. Preserve the two-service topology and non-root PHP user.

### Follow-up advisory and configuration

Rechecked the primary [PHP follow-up](https://www.php.net/archive/2026.php#2026-10-23-1) and
[NGINX advisories](https://nginx.org/en/security_advisories.html) on 2026-10-24. PHP 8.5.12 fixes the two original
CVEs, not CVE-2026-115560. Owned `src`, `config`, and `etc` contain no serialize-handler runtime switches;
CLI and FPM report handler `php`. The follow-up's unusual configured `php_binary`/`php_serialize` to runtime
`php` switch is therefore not demonstrated here. As bounded defense in depth, startup INI now disables the unused
session-upload-progress feature before request parsing. Both CLI and FPM verify it disabled. Explicit COPY mode
0644 makes that INI readable by the non-root runtime, independent of host file permissions.

`./bin/exec php-fpm -tt` and `docker compose exec -T web nginx -t` passed. FPM master and observed worker retain
UID/GID 1000 (`systemuser`), including after HTTP traffic. PHP settings remain `memory_limit=128M`,
`post_max_size=8M`, `upload_max_filesize=2M`, `max_input_vars=1000`, and `max_input_nesting_level=64`;
FPM request termination remains 60s. NGINX retains its documented `client_max_body_size=1m` default; there is no
container memory cap. No unlimited-memory or TLS-verification workaround was applied. The NGINX configuration
still does not enable TLS, HTTP/3, alias/rewrite, or AIO; no specific exploit reachability is claimed.
