# Install and Verify the Stable Fight Package Baseline

## Outcome

Replace the locked development candidates with stable Common `^1.4` / AccessControl `^0.8`, targeting the latest
verified releases Common 1.4.0 and AccessControl 0.8.0. Integrate exact public contracts and adopt Common's
PHPCS standard without changing the existing build lifecycle in this slice.

## Scope

Yii Composer constraints/lock, required adapter compatibility, code-style alignment, meaningful existing-capability
regressions, and adoption documentation. Do not copy package source or create new business workflows. Use this
main checkout on a dedicated feature branch after TASK-00007 and the TASK-00011 amendment are integrated;
do not bundle gate replacement or TASK-00012's shared-instruction adoption into this PR.

## Acceptance Criteria

- [ ] Lock and installed metadata show stable Common 1.4.0 / AccessControl 0.8.0, or newer stable versions within
      the approved `^1.4` / `^0.8` envelope verified at execution. Remove Fight development pins/aliases; record
      release references and compatibility findings. A newer release outside that envelope needs a scoped
      amendment, not an implicit downgrade or an unapproved upgrade.
- [ ] Inspect release/migration documentation and exact released transaction, messaging, security, and Yii
      adapter signatures; reconcile only demonstrated compatibility needs. Explicitly check `UnitOfWork` versus
      `TransactionalUnitOfWork` handler/binding compatibility and transaction semantics. Do not hide missing
      behavior behind aliases, bypass configured buses, or infer AccessControl workflow support.
- [ ] Existing HTTP/console, security rejection, rollback, and selected integration journeys pass; Yii Mail/Session
      remain unselected and no package-owned policy is copied.
- [ ] Use Common's shipped PHPCS standard with compatible consumer-owned tool dependencies, repository-owned scan
      paths/exclusions, and no suppressed failures.
- [ ] Document exact installed artifacts and reconcile WF-001/map evidence with the approved `^1.4` / `^0.8`
      envelope; do not falsely close the full released-capability inventory or infer new product journeys.
- [ ] Exact Unit-only coverage, all suites, planning validation, and the existing canonical gate pass.

## Verification

Use `./bin/up`, `./bin/composer` for explicit resolution/installation, `./bin/exec` for installed contract/tool
inspection, `./bin/phpunit` for focused checks, and `./bin/build` for the final verdict. Record resolved versions,
references, relevant transitive compatibility changes, suite counts, coverage, and warnings. No release or PR
publication is implied by verification.
